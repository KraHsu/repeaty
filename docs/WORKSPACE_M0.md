## 内容格式边界

新文件采用 LF 结构换行；正文中的 CRLF、孤立 CR 和首尾空行不变。已有文件采用结束 frontmatter 行的换行作为结构换行，答案标记前后各一份结构换行不属于题面 / 答案。两侧缺少预期换行时进入待处理，不猜测或删除正文空白。

默认答案标记与原内容冲突时，新文件编码器按确定顺序选择 `repeaty-answer-1` 等替代标记；代码围栏内的字面标记也参与检查。多个声明边界报歧义。修改已有正文若引入当前标记冲突，暂时报错保留原文件；后续编辑器需要安全修改对应元数据，不能通过改写题目绕开。

YAML 只转换有限的 JSON 值，拒绝标签、锚点、别名、重复键、复杂键和非有限数值。限制元数据 1 MiB、深度 32、125,000 个节点，整个文件 2 MiB；沿用每面 10,000 字符和来源 250,000 字符的正文约束。这些是原型的显式边界，不能将超限旧内容截断后宣称迁移成功。现有较大的合法插件 JSON 已有往返样例。

字节入口使用严格 UTF-8；无效字节或无法无损编码的孤立 UTF-16 代理项明确失败。M2 须保留原输入并报告这类来源，不能静默替换为 `�`。

已实现的正文编辑保留原 frontmatter；需要改卡组、标签、附件或类型的元数据编辑器尚未实现，不能用整块 YAML 重新格式化代替无损编辑。

## 只读清点协议

1. 调用者必须显式提供 IDBFactory、库名、偏好读取器，并保证相关写入者已经暂停。没有默认来源、自动发现真实库或 UI 入口。
2. 先确认库存在，再不指定版本地打开。主库的白名单表在同一 readonly 事务内读取；不调用会升级和写检查点的 `createRepository()`。
3. LeetCode 草稿只取 `local:<原库名>` 作用域；旧裸键仅归入 `local:repeaty`。另一账户或库的草稿不放进快照。MCP 草稿及独立上传的 Blob 单独保留。
4. 偏好仅取语言、站点、已知显示 / 通知字段和插件布尔开关，不读上游令牌、地址或其他 localStorage 项；未知字段产生报告。快照不代表恢复 MCP 分享或执行授权。
5. 按类型、原值和 Blob 的 SHA-256 计算指纹；逐个读取 Blob，每个仍受旧库 10 MiB 上限约束。摘要表不是提交正文；缺少代码 / 判题详情、孤立摘要、损坏附件和未知布局明确报告。
6. 分别重新读取主库、对应草稿及偏好并比较完整指纹。任一变化返回 `source-changed`，不交付可供后续迁移的快照。代码、草稿或偏好未增加主库修订号时也能检测到变化。

两次指纹比较不提供跨库原子快照，也不能检测变更后又复原的 ABA。`writersPaused` 是调用者必须满足的前置条件，尚未实现真实应用的停写协调器。`ready` 仅表示本次清点读取稳定且轻量检查未发现缺项，不表示迁移完成或所有业务引用已经校验。

旧 monolithic 布局原样保留并标记 `legacy-normalization-required`；将来只能在副本上正规化。当前原型不包含 `.repeaty` / JSON 文件、服务端 SQLite、账户 API 或桌面设备配置的读取器。

## 复现

```bash
npm ci
npm run test:workspace
```

首批 90 项测试通过，全部使用人工正文、临时内存库和合成附件：

- 中文、emoji、HTML、公式、代码围栏、plain、空答案、未知属性、BOM、混合正文换行及分隔符冲突的往返。
- 重命名、移动、路径互换、复制 ID、改写 / 移除 ID、半写入、重复扫描、缺失提议和变体恢复。
- 多级来源与旧引用、版本不符拒绝、范围越界及 emoji 边界。
- IDB v2 / v16 读取不升级、不写入；缺失与删除竞态；完整代码与判题详情、未完成草稿、附件和作用域隔离。
- 主修订号不变时的代码 / 结果 / 草稿 / 附件 / 偏好变化注入。
- 合计 128 MiB 媒体、原媒体 ID、浮点精度与字节指纹；单个超限 Blob 在读取字节前拒绝。

这里的 128 MiB 是合成 Blob 的只读内存测试，不是安装包迁移、媒体解码或性能验收。真实 Windows / macOS / Linux 编辑器、重启、磁盘与性能矩阵仍待验证。

### CI 排障与复验

- [macOS 失败记录](https://github.com/KraHsu/repeaty/actions/runs/40207988006)：并行测试的子进程继承根目录锁描述符，父进程只关闭文件时，锁可能仍被子进程持有。`RootLock` 现在显式解锁，另用真实 `fork` 与管道构造回归样例；修复前可稳定复现，修复后不靠延时或重试通过。
- [Linux 桌面失败记录](https://github.com/KraHsu/repeaty/actions/runs/40200251697)：摘录导航返回后，测试只等待纯文本节点，漏掉合法的 Markdown 预览。等待条件现在同时识别两种正文视图，仍检查标题和加载结束。
- 提交 `4651933` 的[完整 CI](https://github.com/KraHsu/repeaty/actions/runs/40275269928) 已通过，三平台原生与跨语言测试数量见[内容接受记录](WORKSPACE_ACCEPTANCE.md)。浏览器测试为静态版 73 项、服务端 46 项通过；没有跳过失败样例或关闭失败通知。
- 同一提交的 [Desktop](https://github.com/KraHsu/repeaty/actions/runs/40275269868) 全部通过：三平台安装包与无图形会话 MCP stdio、Linux 桌面浏览器 55 项及真实 WebKit / Rust IPC。原摘录导航失败点已执行通过。这里没有代替 Windows / macOS 的实际安装与 GUI 验收，也未发布新版本。

M0 未通过前不启用真实库自动迁移；现有发布清单也不因这些原型测试而勾选。

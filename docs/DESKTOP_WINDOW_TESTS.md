# 桌面窗口手动验收

[返回桌面文档](DESKTOP.md#窗口标题栏)

这份清单用于当前开发分支的真实桌面窗口。自动测试验证代码、坐标计算和接口调用，不能证明 Windows 11 已弹出系统 Snap 菜单。下面的实机结果均待手动填写；未测试项保留“待测”，没有相应设备或已有草稿时记“不适用”，不记为通过。

## 开始前

1. 关闭旧的 Repeaty 测试窗口；若终端仍运行开发服务，按 Ctrl+C 停止。在仓库根目录运行：

   ```bash
   npm run desktop:dev
   ```

   等 Rust 编译完成并出现窗口。`npm run dev:desktop` 只启动前端服务器，不会打开软件；仅热更新页面也不能替代本次原生代码重启。

   若本机已有本轮构建好的调试程序，也可以直接运行 `./src-tauri/target/debug/repeaty-desktop.exe`，无需等待开发服务器。该程序已包含界面资源；修改源码后须重新构建，不能用旧程序验收新提交。

2. 在 Windows「设置 → 系统 → 多任务处理」确认已开启贴靠窗口，以及悬停最大化按钮时显示贴靠布局的选项。可以先在记事本悬停最大化按钮作系统基线；若记事本也不显示，先记录该设置或系统环境问题。参考 [Microsoft 的 Snap 使用说明](https://support.microsoft.com/en-us/windows/experience/snap-your-windows)。
3. 在 Repeaty 中选择一个**新建的空临时文件夹**创建学习库。新建“窗口验收”卡组，保存一张带明显标记的普通卡片，并在该卡组完成一次评分，记下题目和评分记录，用于检查重启后数据是否保留。本轮无需登录网站、配置 MCP 或安装额外工具，不使用日常学习库做关闭测试。
4. 记录本次环境：

   ```text
   Repeaty 提交：                  （可运行 git rev-parse --short HEAD）
   Windows 11 版本 / OS 内部版本： （设置 → 系统 → 系统信息）
   显示器分辨率 / 缩放：           （例如 1920×1080 / 125%）
   显示器数量与排列：              （副屏在主屏左侧 / 上方等）
   Snap 与悬停布局选项：开启 / 关闭
   测试日期：
   ```

窗口最小内容区为 **500×400 逻辑像素**。显示缩放会改变对应的物理像素；系统边框也可能额外占用像素。Snap 的布局种类取决于屏幕大小、方向和可用工作区，不要求不同屏幕出现相同菜单，也不要求窗口进入小于最小尺寸的分区。[Microsoft 的尺寸说明](https://learn.microsoft.com/windows/apps/desktop/modernize/apply-snap-layout-menu#what-if-my-apps-window-shows-snap-layouts-but-isnt-snapping-properly)

## Windows 11 必测项

每项完成后勾选，并在反馈中注明“通过”或“失败”；不要用勾选代替失败说明。

- [ ] **S01 · 原生 Snap 悬停菜单**：在普通窗口中，把鼠标停在右上角最大化按钮中央约 1–2 秒，不点击；再测试按钮边缘和最大化后的还原按钮。应出现 Windows 自身的布局菜单，按钮高亮正常；窗口不应自行移动、最大化或还原。
- [ ] **S02 · 选择与取消布局**：选择一个能容纳 500×400 内容区的分区。窗口应进入对应工作区，正文和窗口按钮仍可用。再次打开菜单后移开鼠标，菜单应自行消失；随后点击最小化或关闭按钮附近时，不应触发遗留的 Snap 热区。
- [ ] **S03 · 单击只执行一次**：单击最大化按钮，再单击还原按钮；各重复数次。每次只切换一次，不能瞬间最大化又还原；悬停菜单出现后再单击也应如此。按钮上的图标和提示应与实际窗口状态一致。
- [ ] **W01 · 普通拖动**：按住标题栏空白处向四周拖动并松开。窗口应跟随移动，松开后停止；从按钮处按下不会拖动窗口，正文中的拖动或文字选择也不应变成移动窗口。
- [ ] **W02 · 最大化后拖动还原**：先最大化，再从标题栏空白处向屏幕中间拖动。窗口应按 Windows 的行为还原并继续移动，按钮状态同步，不应跳出屏幕或留下无法点击的区域。
- [ ] **W03 · 双击标题栏**：双击标题栏空白处，最大化；再双击，还原。不要双击控件按钮。单次双击只能切换一次，不能同时开始异常拖动。
- [ ] **W04 · 八方向缩放与最小尺寸**：在还原状态分别拖动上、下、左、右四条边和四个角。光标及缩放方向应正确；缩到最小时不低于约 500×400 逻辑像素，窗口按钮、导航和必要操作仍能触达；放大后不应保留旧位置的 Snap 热区。
- [ ] **W05 · 最大化工作区**：最大化后，窗口不应盖住常驻任务栏，四周无异常白边或被切掉的按钮。若原本开启了自动隐藏任务栏，再检查从屏幕边缘能正常唤出它；无需为此更改任务栏设置。
- [ ] **W06 · 最小化与恢复**：点击自绘最小化按钮，确认窗口从桌面收起，应用仍可从任务栏恢复。恢复后，原来的学习库、页面和窗口状态正确；再次悬停最大化按钮仍能显示 Snap 菜单。
- [ ] **W07 · 键盘窗口按钮**：用 Tab / Shift+Tab 将焦点移到窗口按钮，按 Enter 或 Space 执行最大化 / 还原；再测试最小化并从任务栏恢复。应有可见焦点，每次只执行一次，学习记录不应变化。
- [ ] **W08 · 标题栏与滚动区域**：打开「数据与备份」或较长的设置页，滚动到末尾；分别在普通窗口、最大化及500×400最小窗口检查右侧滚动条。轨道应从标题栏下方开始，不能覆盖关闭按钮或让标题栏一起滚走。再打开「帮助」，滚动弹窗正文；标题栏仍固定、弹窗标题不被后台通知遮住，关闭弹窗后页面保留原滚动位置。
- [ ] **M01 · 弹窗中的窗口操作**：打开「快捷键」弹窗，在弹窗保持打开时测试 Snap、最大化 / 还原、拖动、缩放和最小化 / 恢复。窗口按钮应仍能操作，恢复后弹窗仍在；关闭弹窗后，标题栏只有一份，仍可操作。
- [ ] **C01 · 自绘关闭按钮**：确认测试卡片与评分已经保存，再点击右上角关闭按钮。窗口应正常关闭。重新运行 `npm run desktop:dev` 并打开同一临时库，卡片与评分记录应保留，学习库不应报仍被旧进程占用。
- [ ] **C02 · Alt+F4 与弹窗关闭窗口**：重新打开临时库，打开「快捷键」弹窗，再按 Alt+F4。应关闭整个应用，而不是只隐藏标题栏或只关闭弹窗。重启后检查同一份已保存数据。再打开弹窗，用标题栏的关闭按钮重复一次；两种退出方式应保持一致。

## 按环境补测

- [ ] **D01 · 不同显示缩放**：在现有可用的 100%、125%、150% 或 200% 缩放环境中，重做 S01–S03 与 W04。若为测试调整缩放，记下原值并在结束后恢复。最大化按钮中心和边缘都应命中正确，其他按钮及内容区不能出现错位热区。没有覆盖的缩放比例记“未测”。
- [ ] **D02 · 多屏与负坐标**：有多显示器时，将窗口在不同缩放比例的屏幕之间移动，特别测试位于主屏左侧或上方的副屏。每次移动后重做 S01、S02、W04、W06；菜单应出现在当前按钮旁，窗口不能跳到错误屏幕。单屏环境记“不适用”。
- [ ] **D03 · 页面缩放**：若本机 WebView 提供页面缩放操作，改变页面缩放后重做 S01–S03，再恢复原比例；标题栏视觉按钮和原生热区应仍重合。没有可用的页面缩放入口时记“不适用”，无需安装工具或通过修改应用源码强行开启。
- [ ] **M02 · 嵌套弹窗**：临时库已有待确认制卡草稿时，打开「制卡草稿 → 检查并编辑」，在两层弹窗同时存在时重做 S01、S03、W06；依次关闭上层、下层，标题栏应始终只有一份且可操作。没有现成草稿时记“不适用”，本轮不要求额外连接 MCP。
- [ ] **C03 · 已保存草稿重启保留**：仅在临时库已有待确认制卡草稿时，输入可辨识的修改，点击「保存草稿」并确认成功，再分别用关闭按钮、Alt+F4 退出并重启。重新进入「检查并编辑」，内容应保留，未确认草稿不应变成正式卡片或新增评分。普通添加 / 编辑卡片表单没有自动草稿保证；不要用未保存表单代替此项。
- [ ] **P01 · 其他平台回归**：有 macOS / Linux 测试设备时，测试自绘标题栏的拖动、缩放、窗口按钮及弹窗行为。Windows 的 Snap 接入在这些平台不生效，不应留下原生覆盖区或报错；不要把“不显示 Windows 菜单”记为失败。没有相应设备时保留“未测”。

## 反馈格式

通过项可以合并报告，失败项逐项写步骤。例如：

```text
提交：
Windows / OS 内部版本：
屏幕 / 缩放 / 排列：
Snap 设置：

通过：S01、S02、W01、W04……
失败：S03
  操作：悬停最大化按钮出现菜单后，单击最大化。
  预期：只最大化一次。
  实际：最大化后立即还原。
  复现：每次 / 偶发（约几次中出现几次）
  截图或短录屏：可选
未测 / 不适用：D02（单屏）、M02/C03（无现成草稿）……
```

完成反馈前，人工验收状态仍为待验证。最终记录应区分代码检查、浏览器夹具测试、当前机器实测及其他尚未覆盖的平台与显示环境。

# 桌面工作目录预览

> 历史实验记录：以下内容描述 M0 独立目录，不是当前桌面存储。正式目录已由 [工作目录方案](WORKSPACE_MODE.md) 接管；不提供实验格式迁移。

这是工作目录方案的客户端接入批次，尚未发布。后续以桌面客户端为主要体验入口，继续复用现有 Vue 界面与调度；网页和自托管端保留兼容。产品版本仍为 0.27.0，没有创建另一个桌面产品。

## 进入预览

在本分支运行 `npm run desktop:dev`，打开侧边栏「工作目录」。

- **创建预览目录**：通过系统选择器选择一个空文件夹，生成独立的 M0 实验目录。非空目录拒绝创建，已有文件保留。
- **打开目录**：通过系统选择器打开已有的实验目录，检查格式、数据库身份与锁。普通 Markdown 文件夹、旧学习库和不兼容格式不会被初始化成空库。
- **最近打开**：只保存本机选择过的路径与工作目录身份。重新打开会再次核对身份；路径被替换时不能仅凭原地址继续访问。
- **关闭目录**：释放目录及同身份副本的会话锁，撤销旧读取令牌，保留目录和最近记录。再次打开同一目录会产生新会话。
- **重新扫描**：检查 `notes/`、可选的 `sources/` 和 `drafts/`，查看工作文件与已接受正文。文件缺失、错误、身份冲突和改名只产生诊断，不自动消费草稿、制卡、评分或接受修改。

预览独立于当前学习库。制卡、复习、MCP 与 LeetCode 仍使用现有仓库和作用域；这个入口不执行迁移，不把 IndexedDB 换成目录数据库。创建的仍是 `prototype.json` 版本 2 / `state.prototype.sqlite3` 版本 1002，不是正式的 `workspace.json` 格式。

## 客户端行为

关闭应用后，最近选择会保留；再次进入预览时尝试重新打开。目录丢失、权限不足或身份变化时显示诊断，不重新创建目录，也不影响现有学习库。目录重新可用后，“重试”按原选中路径与登记身份重新连接，不改为打开最近列表中的其他目录。读取配置和目录都在后台线程按需启动，创建主窗口时不访问记住的磁盘路径。

文件原文和已接受版本可分别查看。正文按原文本显示，HTML、图片地址和插件数据不执行、不联网。中文、emoji、BOM、CRLF 与原注释不重写。缺少工作文件时，仍可查看保留的已接受正文。

Markdown 校验与变更分类在 Worker 中进行，界面一次渲染 50 个文件，可分页或按路径搜索。扫描只由预览页操作触发，复习评分不扫描目录。这个批次没有新增文件监听、自动接受、冲突解决编辑器或完整学习状态仓库。

较矮的桌面窗口中，导航和卡组列表共同滚动，品牌与底部状态保持固定；底部区域不会挡住新建卡组。设备配置首次读取失败后可重新尝试；关闭或重连会话只处理本窗口原先选中的目录，不会清除另一窗口的选择。

系统目录选择器从用户主目录打开，不依赖桌面会话是否记住了初始位置。主目录只是选择器起点，仍须用户选择文件夹后才打开工作目录。

## 原生边界

新路径只能来自系统目录选择器。最近记录只允许打开设备索引中已登记的路径 / 身份组合，前端没有通用文件系统读写接口。只有主窗口拥有这些 IPC 权限。

每次切换带设备会话代次；选择器打开期间若会话已变化，迟到的选择结果在创建或打开前就会被拒绝。读取使用会话令牌，关闭后的旧请求失效。新目录或设备索引写入失败时保留原会话，不先关闭旧目录再尝试新目录。

读取通过持有的目录句柄进行，检查目录本体未被替换，并用 [cap-std](https://docs.rs/cap-std/4.0.3/cap_std/fs/struct.Dir.html) 限制相对读取。链接、FIFO、无法稳定读取或错误编码的文件不会作为正文展示；不完整扫描不会据此提出删除。M0 的绝对路径保存原语尚未改造成正式的目录能力写入器，不能把本批只读扫描的证据扩展为所有编辑器 / 对抗目录替换 / 断电场景已通过。

当前扫描限制：单文件 2 MiB；接受正文与工作正文合计 32 MiB；最多各 4,096 条接受记录和工作文件；遍历深度 12、目录项 20,000。超限明确停止或返回不完整结果，不截断后当作成功。这里的正文预算不是完整迁移或整库性能验收。

设备索引位于应用数据目录的 `workspace-preview.sqlite3`，同身份锁位于 `workspace-preview-locks/`。它们只保存本机入口，不进入便携目录，也不授予 MCP 分享、插件执行或上游账户权限。预览不发布学习内容，但会维护设备入口、目录锁和原型数据库连接，因此不宣称整个磁盘零写入。

## 验证

```bash
cargo test --locked --manifest-path crates/workspace-store/Cargo.toml
npm run test:workspace
npm run test:workspace:native
# 构建桌面程序后；Linux 另需 WebKitWebDriver、tauri-driver、Xvfb、xdotool
xvfb-run -a node scripts/test-workspace-preview-native.mjs
# 不依赖已登录桌面会话的 GTK / D-Bus 回归
GSETTINGS_BACKEND=memory GTK_USE_PORTAL=0 GIO_USE_VFS=local \
  dbus-run-session --config-file=scripts/fixtures/minimal-desktop-session.conf -- \
  xvfb-run -a node scripts/test-workspace-preview-native.mjs
```

原生新增 11 项测试覆盖重启、关闭与旧令牌、选择器代次、最近身份变化、索引写失败、同身份副本、非空目录、中文正文、错误编码、链接、FIFO 和目录替换。前端新增 13 项覆盖变更投影、异步会话、HTML 转义、版本切换、双语及列表分页 / 搜索。

本地已通过 Rust 41 项、跨语言 23 项、全量单元 442 项（另 1 项既有跳过）、类型与构建检查。真实 Linux WebKit / Rust IPC 流程通过系统选择器创建 / 打开 / 取消、最近重开、外部改名 / 修改 / 重复身份 / 缺失、旧版本读取和实际应用重启；同时核对原学习库、调度 JSON、操作与变更记录不变。1280 与 720 宽度检查无横向溢出，并检查英文界面截图。桌面浏览器 58 项全量回归通过，包含三项短窗口用例；另有 Tauri 延迟初始化失败后重试的测试。

直接 `cargo build` 的开发二进制需要桌面开发服务；`npm run desktop:build -- --debug --no-bundle` 生成包含前端的调试程序，可在关闭开发服务后运行原生测试。`npm run desktop:build -- --no-bundle` 生成的 release 程序也已本地通过原有完整原生流程，以及最小桌面会话中的工作目录完整流程，无需开发端口。`main` 的 Desktop CI 使用安装包构建的 release 程序，在原有全量原生测试之后运行本套件，保留宽 / 窄窗口截图。功能分支只跑单元测试。三平台结果按实际运行的提交另记，不用本机测试替代 Windows / macOS GUI 验收。

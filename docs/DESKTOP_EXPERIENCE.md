# 桌面启动、更新与诊断

“设置 → 通用 → 桌面”提供设备级选项。它们保存在应用数据目录，随学习库移动的备份不包含这些设置。

## 启动与后台

- 登录启动使用系统登录项，仅安装后的构建可设置；开发进程不会被注册到系统启动项。显示的是注册状态，系统管理员或系统设置仍可能禁用启动项。
- “登录启动时隐藏窗口”只影响系统传入的 `--background` 启动。手动启动或重复打开会显示已有窗口，不会创建第二个实例。CLI 和 MCP stdio 模式保留独立进程行为。
- “关闭窗口后留在后台”默认关闭。开启后，关闭请求仍经过原有编辑确认与学习库保存流程，成功后才隐藏。托盘提供打开与退出；退出也经过同一保存流程，取消保存会取消退出。
- 托盘创建失败时保持可见窗口和正常关闭行为，不会留下无法找回的后台窗口。Linux 桌面是否显示托盘取决于桌面环境。
- 全局收集继续使用“快捷收集”的既有设置；后台模式不改变其按学习库授权和保存约束。
- 窗口记忆大小、位置和最大化状态。隐藏状态与系统装饰不参与恢复，因此不会覆盖登录启动的可见性或自绘标题栏。更换显示器和 DPI 后的实际行为仍需逐平台验证。

## 更新

未配置签名渠道的构建只读取固定官方 GitHub 仓库的稳定 release 信息，显示版本说明与官方页面链接。网络失败保留已显示结果；开发构建同样不会提供安装按钮。应用不会自动发布版本或运行下载的非签名安装包。

签名渠道由发布维护者配置，不能由插件或普通设置替换：

1. 构建时设置 `REPEATY_UPDATER_PUBLIC_KEY` 为 Tauri updater 的公钥。私钥不进入代码、学习库或用户配置。
2. 官方仓库稳定 release 中提供 `latest.json`，固定入口为 `https://github.com/KraHsu/repeaty/releases/latest/download/latest.json`。使用 Tauri 平台清单，安装包 URL 必须位于本仓库的 `releases/download/`。
3. 发布与当前官方 updater 匹配的签名包，签名必须绑定应用版本（Tauri signer 的 `--app-version`）；还需针对每个平台验证安装、重启和回退。当前发布脚本尚不产出该渠道，不应仅设置公钥就宣称升级可用。

更新元数据上限 1 MiB，安装包上限 512 MiB；只允许 HTTPS 和官方 GitHub 下载重定向。下载可以取消，取消或验证失败不会进入安装。下载完成后由用户选择“保存并安装更新”，沿用编辑/保存确认；拒绝保存不安装。安装前再次验证签名；版本不高于当前版本不能安装。失败时不主动关闭学习窗口。成功后使用平台安装器/重启流程。

已下载的包只保存在当前进程内，退出后需要重新下载；未实现静默安装。macOS/Windows 安装与 Linux AppImage 的具体系统限制以 Tauri updater 为准；目前 Linux 分发为 deb，不能把 AppImage 更新流程标作 deb 升级验收。

## 诊断

报告必须先预览，再复制或导出为 JSON；不自动上传。固定字段只有应用/版本、平台/架构、开发构建标志、缩放因子、最大化状态、托盘、登录启动、签名渠道和设置读取状态。没有学习正文、设备路径、令牌、原始异常、机器名或用户标识。

## 人工验证

每个平台单独记录结果：安装版登录启动/系统禁用、隐藏后托盘唤回、重复启动、后台全局收集、保存取消/失败后的关闭与退出、自绘标题栏拖动/缩放/最大化、Windows Snap、100%/150%/200% DPI、签名更新的成功/拒绝/断网/取消及安装后数据读回。单元测试和浏览器夹具不能替代这些原生实机验证。

实现依据：[Tauri autostart](https://v2.tauri.app/plugin/autostart/)、[single instance](https://v2.tauri.app/plugin/single-instance/)、[updater](https://v2.tauri.app/plugin/updater/)。

# 局域网设备同步

桌面版在「设置 → 连接 → 设备同步」提供同一局域网内的学习库同步。两台设备分别保存自己的工作目录；同步交换领域事件和按内容哈希标识的附件，不复制正在使用的 SQLite 文件，也不依赖账号或云服务。

## 配对与交换

1. 在第一台设备打开学习库，填写本机私有 IP 和端口，例如 `192.168.1.8:43127`，创建同步组并设置监听地址。回环地址只能用于本机连接。
2. 生成邀请，将邀请交给另一台设备的使用者。邀请包含连接地址、公有证书和限时一次性票据，应只交给自己信任的设备。
3. 在第二台设备打开目标工作目录，填写它自己的监听地址，粘贴邀请并申请加入。在第一台设备核对申请设备后批准。
4. 选择交换更新。两端需要能够互相访问所选端口；系统防火墙可能需要允许 Repeaty 使用私有网络。
5. 交换结束后预览收到的更新，处理冲突，再确认合入。另一台设备也需要确认合入；有冲突解决结果时再交换一次，使各端获得解决事件。

同步组已建立的学习库不能直接改为另一个组。可先退出同步组，再重新配对。退出停止本机连接和配对授权，保留学习内容、插件数据及归档的旧同步日志。

## 接收与合入

接收只写入事件暂存和附件对象。复习、阅读和编辑中的内容不会被远端推送替换。合入要求当前学习库没有进行中的学习或编辑操作，并再次检查预览时的库修订号和事件进度。

合入使用原有学习库保存事务：卡片、调度、历史、退役记录、插件数据和已应用的事件进度一起提交。失败时不提前推进已应用进度。工作目录中已被外部编辑的 Markdown 和附件仍受原有覆盖检查保护。

同步合入建立本地撤销边界，之前尚未执行的撤销/重做不能跨越同步改写其他设备已修改的内容。已记录在同步日志中的撤销仍按原事件传播。

## 冲突与历史

每个修改事务都有独立身份和因果向量。重复传输不产生重复评分；乱序到达的事件等待前序事件。相同事件身份携带不同内容会被拒绝。

不同字段的独立编辑可自动合并。同一字段的不同修改、删除与编辑冲突，需要明确选择本机或另一设备的内容。选择产生新的因果解决事件，不用设备时钟决定谁覆盖谁。

两台设备离线复习同一张卡时，双方独立的评分历史均保留，后续调度由用户在实际产生的两个调度分支中选择。系统不会根据缺失的历史 FSRS 参数重新编造一次评分回放。删除或退役与远端学习并发时，历史保留在退役记录中；无法满足题型、变体或引用约束的结构合并会阻止提交，不能用丢弃历史来强行通过。

## 附件与插件

附件按固定大小分块传输，每块和完整对象都核对 SHA-256。中断后保留已验证块，重试仅传缺少的块。完整对象验证完成后才登记到对象库；用户确认合入时才发布工作目录中的附件。相同内容可复用，未完成文件不能成为学习内容的引用。

同步包含笔记和材料数据、版本引用、完整评分与代码历史、插件题目数据，以及公开 SDK 存储的插件配置和 JSON 数据。未知或未安装插件的内容仍保留。

接收端根据已接受的笔记领域内容生成可编辑 Markdown。材料的属性随材料保存；笔记中不属于宿主模型的自定义 YAML 字段、注释和原始排版模板不会自动映射到新设备。已有本机模板继续由原有编辑器保留，整体文件保真请使用完整备份或工作目录复制。

插件代码包、插件私有文件目录、本机登录凭据、来源目录授权和代码信任不通过此同步通道传播。需要的插件在每台设备上独立安装并授权；同步不会自动执行另一台设备的代码。整体移动或备份工作目录时，仍遵守原有插件文件随库保存的规则。

## 连接与设备边界

网络监听默认关闭，应用重启后需要重新开启监听。暂停停止交换；移除设备使其在本机的已有连接和授权失效。每个请求同时检查当前工作目录作用域，切换或关闭学习库会取消旧会话。

邀请使用限时票据和完整证书固定，批准后的数据连接使用双向 TLS。私钥与配对授权保存在设备应用数据目录，随学习库复制不会复制本机身份。诊断只提供协议、数量和错误分类，不包含邀请、密钥、学习正文或路径。

当前通道面向桌面局域网直连，不提供公网中继或自动端口映射。浏览器只读工作目录不会启动监听，也不会因此写入原目录。

## 文件格式

首次建立同步组时，同一事务将工作目录的 SQLite `user_version` 提升为 18；旧客户端会拒绝写入。`workspace.json` 标记仍为 3，学习库 payload 和 JSON 备份仍为 19。只读网页可以读取结构 18 的学习数据，忽略设备同步日志。

同步日志及暂存对象用于幂等重试与恢复，不应手工编辑。完整备份保留库内日志；恢复出的新工作目录具有新的库身份，生成新的本机事件写入者，避免与原库重用事件序号。

单次预览最多处理 10 万条事务、10 万项记录变更和 64 MiB 事件内容。超过限制会明确停止预览，保留已接收日志，不部分合入、不推进应用进度；当前不会自动拆开一个超过预览上限的待处理集合。附件独立分块传输，继续使用现有图片/音频和文档大小上限。

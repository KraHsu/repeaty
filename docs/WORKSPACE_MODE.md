# 桌面工作目录

Repeaty 以桌面客户端为主要产品。一个学习库对应一个文件夹，客户端直接打开它；不再在桌面端区分本地学习库与上游账号模式。在线页面保留体验用途，同步服务另行设计。

本轮按项目尚无其他使用者处理，直接建立新格式，不开发旧 IndexedDB、上游账户或实验目录的迁移和双写机制。程序不会自动读取、删除或覆盖旧库。M0 文档与测试保留为协议实验记录，不代表正式目录支持这些实验格式。

## 使用

在侧边栏「工作目录」中选择空文件夹创建学习库，或打开已有的 `workspace.json` 所在文件夹。新建库自动添加入门卡组。下次启动会重新打开上次选择的目录；目录不可用时显示重新打开入口，不创建替代库。

关闭目录前会等待正在保存的操作。重新打开、切换与重启都会取得新会话；旧页面的延迟请求不能写入新目录。同一学习库不能由两个客户端进程同时编辑。

```text
我的学习库/
├── workspace.json             # 目录格式与学习库身份
├── notes/*.md                 # 卡片正文，含稳定笔记身份
├── sources/*.md               # 材料正文
├── assets/<sha256>.<扩展名>    # 图片、音频与不可变原文快照
└── .repeaty/
    ├── state.sqlite3          # 卡组、卡片映射、FSRS、复习与代码记录
    │                          # 阅读位置、检查点、AI 草稿、偏好与代码草稿
    ├── objects/<sha256>       # 已接受的 Markdown 原字节
    ├── staging/               # 待发布正文
    ├── retained/              # 替换下来的原文件
    └── workspace.lock         # 打开期间的写锁
```

正式目录格式为 2，产品版本仍为 0.27.0。格式 1 属于此前未发布的接管实现，当前不自动迁移；测试时请创建新目录。SQLite 的内部结构编号不另作产品版本。

## 保存与备份

应用内制卡、编辑、评分、撤销、材料阅读和 AI 草稿使用同一个 Rust 存储。正文进入 Markdown；学习状态、映射与增量历史进入 SQLite；附件单独存为文件。评分只更新发生变化的记录，不扫描或重写整个正文目录。

SQLite 接受记录与正文发布意图在同一事务提交。文件以完整候选文件发布，实际被替换的原文件保留在 `retained`；中断后重新打开会处理待完成的发布。外部文件不符合保存时的基线会报告冲突，不按旧缓存覆盖。

复制、移动或备份前请先关闭学习库。应复制整个目录，包括 `.repeaty` 和 `assets`；只复制 Markdown 不包含学习进度。正在打开的 SQLite 可能存在 WAL 文件，不把热复制当作可靠备份。应用里的 `.repeaty` 导出包含当前学习库，不包含退役记录、待确认草稿和目录偏好；完整备份应复制整个已关闭的目录。

## 外部 Markdown 编辑

外部编辑器可修改和改名已有笔记正文。在「工作目录」重新扫描后，可比较磁盘文件与已接受版本，再接受修改。接受时复用原笔记和卡片身份，不重置当前调度；BOM、CRLF、YAML 注释和无关属性尽量按原字节保留。

新增笔记可以直接放入 `notes/`。问答和双向卡的题面与答案用单独一行 `<!-- repeaty:answer -->` 分隔；挖空卡可直接写 `{{c1::答案}}`。重新扫描后选择「接受修改」，确认卡组、题型和格式。普通 Markdown 或缺少身份的文件会取得稳定笔记 ID 并写回原文件；已有 YAML 注释、无关属性与 BOM / CRLF 尽量保留。带 `repeaty.id` 的文件沿用原身份。

方向和挖空编号发生变化时，确认页会显示保留、恢复、新增和退役数量。已有卡片保留当前调度；新增变体才创建新卡；移除的变体退出学习队列，代码、评分和练习记录保存在同一个 SQLite 中。重新添加相同变体时恢复原 Card ID、调度和历史。桌面应用内的编辑也使用这套规则。

外部删除文件后，重新扫描并确认「移除这条笔记」才会退出学习队列。「已移除的笔记」可搜索、分页和恢复，原路径已有其他文件时可指定另一个 `notes/` 路径。应用内删除笔记或卡组也保留笔记记录；原卡组已删除时，可在恢复确认页选择另一个卡组。当前会话的撤销可恢复原文件路径；重启后通过移除列表恢复。

确认前会再次核对工作目录中的文件观察结果，防止把已改名或刚恢复的文件当成已删除。非法内容、重复身份、无法完整扫描或路径碰撞会停止操作，失败的事务不会留下半份退役记录。仅改变记录顺序时在 SQLite 中调整位置，不读取、传回或改写未变的 Markdown 和代码正文。

材料正文版本接受、外部附件编辑和自动监视仍待后续实现。材料文件会被列出，原有快照与摘录继续保留；不能把 M0 的独立实验算作这些功能已接入。

目录扫描有文件数、深度和字节限制，并在线程 / Worker 中处理。扫描不完整、路径不安全或内容无效时停止处理，不把未读到的文件当成已删除。文件内容以文本展示，不执行其中脚本。

## 随目录携带与留在设备上的数据

随目录保存：卡组与卡片、调度与历史、阅读安排与位置、材料快照与附件、MCP 待确认草稿、LeetCode 未提交代码、语言、通知、答题历史及插件开关。

留在设备上：最近目录列表、窗口配置、MCP 访问授权、LeetCode 登录凭据。复制学习目录不会复制登录信息；新的设备需要重新授权。工作目录内的插件数据不会授予原生执行权限。

目前没有文件同步引擎、云服务或订阅。本轮不部署私有 IAM 服务，也不改动已安装的客户端。

## 验证入口

- `npm test`：共享核心与界面单元测试。
- `npm run test:workspace:native`：TypeScript 仓库与真实 Rust 目录协议联测，包括重启、目录复制、媒体、草稿、会话和千张卡的评分写入范围。
- `cargo test --manifest-path crates/workspace-store/Cargo.toml --locked`：原生保存、恢复、锁与路径测试；其中 `prototype` / `preview` 属于早期实验。
- `npm run test:e2e:desktop`：桌面界面回归，存储连接真实 Rust，测试替代 OS 选择器与插件联网。
- `scripts/test-workspace-native.mjs`：真实 Tauri / WebKit 与系统文件夹选择器验证，运行前需构建包含前端资源的客户端。

跨平台安装包和完整端到端 CI 只在 main 执行；功能分支只跑基本单元测试。

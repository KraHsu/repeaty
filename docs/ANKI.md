# 导入 Anki 卡组

[使用指南](USAGE.md) · [返回首页](../README.md)

在卡片列表点击「批量导入」，将「导入格式」切换为 **Anki .apkg**，选择目标卡组和文件。查看预览与导入报告后，点击「确认导入」。取消或关闭预览不会写入学习库。

静态、账户和桌面版本使用同一个导入器。文件在本机的独立 Worker 中解析，不上传原始 `.apkg`。账户版确认后，将转换后的笔记和附件保存到所登录的服务；桌面版保存到当前本地库或上游账户库。

## 支持范围

| 内容                                    | 导入结果                                           |
| --------------------------------------- | -------------------------------------------------- |
| Basic，两字段、一个标准问答模板         | 一张正反面卡片                                     |
| Basic (and reversed card)，两个标准方向 | 一条双向笔记、两张独立复习的卡片                   |
| Cloze，Text / Back Extra 两字段         | 每个挖空编号生成一张卡片；支持提示与同编号多处挖空 |
| 加粗、斜体、段落、换行、列表、代码      | 转为 Markdown                                      |
| `\(...\)` / `\[...\]` 公式              | 转为 Repeaty 的行内 / 独立公式                     |
| 包内图片、`[sound:文件名]`、音频元素    | 作为对应面的本地附件；共享文件只存一份             |
| 标签、Unicode                           | 保留，仍受 Repeaty 字段上限约束                    |
| Anki 学习进度、暂停状态和 revlog        | 不导入，所有卡片从新卡开始                         |

模板按字段和结构识别，不依赖英文名称，因此改名或本地化后的标准模板也可导入。第一版限两个字段；输入答案、可选反向卡、多字段、自定义动态模板和图片遮挡会列入跳过报告。挖空编号仍为 1–99，不支持嵌套；文件中缺失的挖空变体不会凭空生成。

支持 `collection.anki2`、`collection.anki21` 的旧版兼容包，以及 `collection.anki21b` 的新版压缩包。已用 Anki **26.9.3** 实际导出的两种包验证；这不代表兼容所有第三方导出器和历史版本。遇到不受支持的压缩格式，可从 Anki 重新导出并开启旧版兼容选项。

## 内容与附件

Repeaty 使用自己的显示方式。导入不保留 Anki CSS、字体、HTML 布局、模板逻辑或内联媒体位置。图片和音频显示在对应面正文下方；请在确认前检查内容预览，导入后试着复习几张卡片。

脚本、事件处理器和交互元素不会执行。外部图片与音频不会下载，并在报告中列出调整项。缺失或损坏的包内附件会导致整条受影响的笔记跳过，避免导入一张没有题目或答案图片的卡片。SVG、视频、LaTeX 编译环境和 Anki 扩展语法不在本版支持范围内。

媒体沿用 PNG、JPEG、WebP、GIF 和 MP3、WAV、OGG、M4A、WebM、FLAC、AAC 格式；导入会核对文件头，新版包还核对媒体大小与 SHA-1。每面最多 8 个附件，每个最大 10 MB。

## 重复导入与失败重试

Anki GUID 编码为稳定的笔记 ID，随 Repeaty 的 JSON、`.repeaty` 备份、快照和账户库存储保留。再次导入相同 GUID 时跳过，**不会更新或覆盖**已经编辑的内容、所属卡组和复习进度；更换目标卡组也不会生成第二份。

预览显示可导入、已存在和跳过的数量。下载报告包含来源笔记 ID、GUID、模板名称和逐项原因，便于回到 Anki 检查。原始 HTML、字段定义、模板和 revlog 不保存在 Repeaty 中；请保留原 `.apkg`，它仍是原始数据的完整副本。

确认后，笔记、卡片和附件引用在一次存储事务中提交，操作前保存快照。保存失败保留预览，可重试；账户版可能留下未引用的已上传附件供重试，沿用现有的过期回收规则。修订冲突需要刷新后重新预览。

## 文件限制

一次最多读取 **5000 条笔记**，`.apkg` 最大 **256 MB**，展开后的 SQLite 最大 **128 MiB**，累计展开数据最大 **512 MiB**。单面正文仍以 10000 字为限，标签最多 20 个、每个 40 字。超出笔记内容范围的条目会列入报告；超出整个文件的限制则拒绝读取。

解析在独立 Worker 中运行，可取消，60 秒仍未完成会中止。SQLite 在内存中读取，确认前也需要持有转换后的内容和附件；这些上限不是所有设备都能处理的容量保证。大卡组建议在 Anki 中拆分导出。

纯前端版将导入器和 SQLite Wasm 一起缓存，离线就绪后可断网导入。自行部署时需允许同源 Worker、Wasm 资源及 WebAssembly 编译；桌面版已配置对应 CSP。

实现入口为 `src/core/anki/`。格式依据 [Anki 的包元数据](https://github.com/ankitects/anki/blob/main/rslib/src/import_export/package/meta.rs)与[导入导出协议](https://github.com/ankitects/anki/blob/main/proto/anki/import_export.proto)独立实现；解析使用 [sql.js](https://github.com/sql-js/sql.js)、[fzstd](https://github.com/101arrowz/fzstd) 和 [parse5](https://github.com/inikulin/parse5)，均以 MIT 协议分发。测试样例与生成方式见 [fixtures](../tests/fixtures/anki/README.md)。

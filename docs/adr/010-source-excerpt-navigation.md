# ADR 010：原文中的摘录导航

- 状态：已实现，随 0.20.0 验收
- 日期：2026-10-20
- 范围：静态版、账户版、桌面本地与上游模式

## 问题

一级摘录可以独立阅读和制卡，但原文页缺少它们的列表。重复文字不能依靠全文搜索判断是否已经摘过，打开稍后阅读或已归档的摘录也不应修改它的安排。

## 决定

原文页增加「本篇摘录」，显示标题、最多 160 个 UTF-16 单元的正文预览、关联卡片数量和非待阅读状态。列表按原文起止位置排序，同位置按创建时间和 ID 排序；包含稍后阅读和已归档的摘录，每页最多五条。卡片数按实际 Card / Note.excerpt 关系统计，包含双向与多个挖空生成的卡片，不是笔记数或到期数。

`core/source-navigation.ts` 只从当前库筛选现有 Source.origin，预览取自已经打开的父原文。列表、翻页和重复检测不读取所有子摘录正文，也不保存派生索引。HTML 与 Markdown 在预览中作为普通文字显示，截短不拆开代理对。

再次选择完全相同的原文 ID、起点和终点时，显示已有摘录数量。「查看已有摘录」跳到第一个匹配项所在页，聚焦列表标题，标出所有可见匹配项。相同文字的其他位置与部分重叠不算重复；已有的同选区多份摘录全部保留，仍可主动另存一份。

## 定位与打开

「定位原文」切换到原始文本，准确选中 UTF-16 范围并聚焦阅读器，滚动到选区开头。Markdown 预览也使用这条路径，避免将渲染位置误当作原文位置。位置继续通过既有自动保存流程保存，不改变任何 FSRS 状态。

普通浏览时，「打开摘录」先保存当前可读原文的位置，再切换到全部材料，清空搜索并跟随目标所在分页，恢复摘录自己的位置。即使目标稍后阅读或已归档，也只打开而不更改其日期或状态。保存失败停留原页，允许重试。原文正文读取失败时没有新位置可保存，可以打开独立正文，原已保存位置保留。

阅读轮次内，「打开摘录」使用现有 SourceContext 弹窗查看正文与出处，关闭后继续原篇。它不改变轮次索引、固定顺序或摘录安排。

异步导航绑定组件生命周期、库作用域、父与子快照 ID。离开材料页、切库或恢复替换快照后，迟到结果不能跳到旧目标。定位也检查阅读器恢复序号，已卸载或后续切换的阅读器不接受旧选区。

## 数据与验证

不新增存储字段或后端接口，沿用 0.19.0 的 Library v10、IndexedDB v13、SQLite v7、API v8、`.repeaty` v7 和 JSON v10。删除与恢复后从现有记录重建列表、计数和匹配结果，脱离出处的摘录不串入其他原文。

领域测试覆盖稳定排序、实际卡片计数、精确重复范围、其他来源与删除、Unicode 预览和记录不变。三版本浏览器流程覆盖长 Markdown、同文不同位置、跨页重复、键盘定位、稍后阅读和归档、双语窄屏、轮次弹窗、删除与备份恢复。

配额与服务故障验证位置保存失败不跳转；服务测试检查正文按需读取和离开页面后的迟到响应。Linux 原生桌面覆盖关联卡片数、选区与焦点、已有摘录跳转、独立阅读器和轮次弹窗，并比较原学习记录。

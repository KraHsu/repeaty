# ADR 015：工作目录模式与旧库迁移

- 日期：2026-10-25
- 状态：提议；仅授权方案制定，未实施。
- 基线：Repeaty 0.27.0。
- 详细方案：[工作目录模式与旧库迁移](../WORKSPACE_MODE.md)。

## 背景

当前客户端分别使用浏览器 IndexedDB、桌面本地 IndexedDB 或远端账户 SQLite。连接上游会切换数据源，本地与远端库并不自动同步。学习数据、未完成草稿、偏好和设备凭据也不都属于同一个备份范围。

用户希望收敛产品形态，采用接近 Obsidian 的本地工作目录、可选同步和免费核心。工作目录需要足以迁移完整学习状态，单纯更改产品名称或合并构建命令不能满足这个目标。

## 提议

1. 学习库使用稳定的 `workspaceId`，不以目录路径、设备或账户作为身份。已有本地库和上游库分别迁入独立目录。
2. 第一阶段建议使用目录内 SQLite 保存结构化内容、调度、历史、草稿与设置，附件放入不可变摘要文件。数据库是权威数据，只有明确声明的缓存可以删除重建。是否要求正文可被外部编辑器直接修改，尚待确认。
3. 保留 Vue、ts-fsrs 和现有 Note / Card / Source / Practice 身份与语义，桌面仍加载本地安装包。浏览器目录能力另做验证；私有身份适配留在服务端。
4. 原库只读取快照，在新暂存目录转换、逐项校验、原子发布，最后选择启用。原库不删除、不在读取时升级，迁移不重新计算调度或重新分配已有媒体 ID。
5. 便携目录包含持久学习状态与库内配置；设备凭据、执行信任和 MCP 分享授权不随目录迁移。来源没有的草稿、检查点与设置必须在报告中说明。
6. 保存成功以本地事务提交为准，后续同步使用事务变更记录与 outbox。复制活跃数据库、全库覆盖和已有上游 API 不能被当作已经实现的离线同步。

## 取舍

SQLite 主方案可以复用当前的事务与结构化模型，适合先由一名开发者完成目录模式和无损迁移；它不直接提供 Markdown 外部编辑，也不支持任意网盘对活跃数据库进行多端并发合并。若这些是必要条件，应在落地格式前改选文件化方案，不能到同步阶段才隐瞒差异。

不预先建设新的 monorepo、Rust / WASM 调度核心、同步后端、支付系统或插件市场。目录、迁移、宿主收敛、同步和私有部署适配按阶段交付，不能把设计草案计为 v1.0 完成项。

## 验证状态

仅完成 0.27.0 源码与格式清点，尚未实现新目录、执行旧库迁移或验证断电 / 多端同步。迁移矩阵和阶段门槛以详细方案为准。其他 ADR 描述的已发布行为仍然有效，直到相应实现通过验证并另行记录。

# ADR 015：工作目录模式与旧库迁移

- 日期：2026-10-25
- 状态：提议；Markdown 外部编辑已确认是首批要求，格式与事务方案待原型验证；未实施。
- 基线：Repeaty 0.27.0。
- 详细方案：[工作目录模式与旧库迁移](../WORKSPACE_MODE.md)、[Markdown 与外部编辑](../WORKSPACE_CONTENT_FORMAT.md)。

## 背景

当前客户端分别使用浏览器 IndexedDB、桌面本地 IndexedDB 或远端账户 SQLite。连接上游会切换数据源，本地与远端库并不自动同步。学习数据、未完成草稿、偏好和设备凭据也不都属于同一个备份范围。

用户希望收敛产品形态，采用接近 Obsidian 的本地工作目录、可选同步和免费核心。工作目录需要足以迁移完整学习状态，单纯更改产品名称或合并构建命令不能满足这个目标。

## 提议

1. 学习库使用稳定的 `workspaceId`，不以目录路径、设备或账户作为身份。已有本地库和上游库分别迁入独立目录。
2. Markdown 外部编辑是首批必要条件。笔记、材料和制卡草稿的正文以普通文件为来源，SQLite 保存调度、评分、练习、身份映射和事务信息。数据库中的正文只是已接受版本的投影，不是另一条独立编辑路径；结构化学习状态仍不能靠 Markdown 重建。
3. 保留 Vue、ts-fsrs 和现有 Note / Card / Source / Practice 身份与语义，桌面仍加载本地安装包。浏览器目录能力另做验证；私有身份适配留在服务端。
4. 原库只读取快照，在新暂存目录生成可编辑文件、状态库和历史对象，反向解码及逐项核验后再发布、选择启用。原库不删除、不在读取时升级，迁移不重新计算调度或重新分配已有身份。
5. 便携目录包含持久学习状态与库内配置；设备凭据、执行信任和 MCP 分享授权不随目录迁移。来源没有的草稿、检查点与设置必须在报告中说明。
6. 文件修改通过身份、语法与引用校验后形成已接受版本。应用编辑写回同一文件，用持久日志协调文件与数据库；SQLite 事务不能被当作跨文件原子提交。冲突保留版本，监听丢失由重新扫描恢复。
7. 普通正文编辑和文件改名保留进度；新增变体才新建卡片，移除的变体退役保留历史。材料修改创建新正文版本，旧摘录继续引用旧版本；这些语义需明确的内容版本、SourceRevision 和卡片生命周期 DTO。
8. 后续同步使用已接受变更与事务 outbox。Markdown 可被文件工具处理不代表全部学习状态已可并发文件合并，也不能把已有上游 API 当作离线同步。

## 取舍

原「SQLite 保存全部正文，Markdown 外部编辑可后续评估」的候选方案不再采用。当前选择 Markdown 与结构化学习状态的混合存储：外部工具可以直接处理内容，同时沿用 SQLite 保存进度和事务的能力。代价是必须首批解决文件身份、内容版本、跨文件保存与崩溃恢复；不能先完成纯数据库写入器，再把这些作为附加小功能。

本方案不是所有学习事件完全文件化。任意网盘对活跃 SQLite 的多端覆盖仍不受支持；若要求全部学习状态也能用通用文件工具并发合并，需要进一步调整其存储和同步协议。

不预先建设新的 monorepo、Rust / WASM 调度核心、同步后端、支付系统或插件市场。目录、迁移、宿主收敛、同步和私有部署适配按阶段交付，不能把设计草案计为 v1.0 完成项。

## 验证状态

仅完成 0.27.0 源码与格式清点和外部编辑设计，尚未实现 Markdown 编解码器、新目录、迁移器或验证并发保存 / 断电 / 多端同步。首项工程验证为脱敏样例的内容编解码与文件变更分类，同时建立只读来源清点协议。迁移矩阵和阶段门槛以详细方案为准，其他 ADR 的已发布行为仍有效。

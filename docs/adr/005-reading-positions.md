# ADR 005：材料阅读位置

- 状态：已实现，随 0.15.0 验收
- 日期：2026-10-19
- 范围：静态版、账户版、桌面本地与上游模式

## 问题

已有学习材料保存不可变的文本 / Markdown 快照，支持摘录制卡和复习时回看出处。长文关闭后只能从开头阅读，缺少可恢复的位置。先补保存与继续，不把阅读队列、优先级或片段树作为前置条件。

## 决定

在 `Source` 上增加可选 `reading`：

```ts
{
  offset: number // 快照中的 UTF-16 位置
  fraction: number // Markdown 块内比例，原文视图固定为 0
  view: 'source' | 'preview'
  updatedAt: string // 本次保存时间，ISO 8601
}
```

原文使用隐藏的纯文本镜像测量换行，将顶部可见行转换为文本位置；恢复时按当前宽度重新计算。位置不截断代理对。Markdown 安全渲染器为顶层块附加原文起止位置，保存块起点与块内比例；列表、表格、代码和公式仍是原有内容。原文 / 预览切换采用近似换算，布局改变后允许一行左右的偏差，不将视口像素作为持久身份。

`SourceReader` 只报告位置，不直接写库。根组件中的 `useReadingProgress` 合并连续滚动，停留 700ms 后调用 `useLibrary.saveSourceReading`；明确保存可立即提交。切到其他页面不会丢弃已排队的保存。保存只修改一条材料元数据，复用修订冲突、事务回滚、快照与媒体引用检查，不修改笔记、卡片、练习、评分或 FSRS 状态。

保存绑定库作用域、材料 ID 和快照媒体 ID。切库时清空旧队列，异步返回不能更新新库的状态；删除或替换材料时移除对应任务。成功恢复备份或快照后清空待保存任务，避免旧位置覆盖恢复结果。失败时保留待保存位置并显示重试，不显示为已保存，也不自动切换到其他存储。

列表显示上次保存时间与「继续阅读」，重新进入材料页时默认选择最近保存位置的材料。没有阅读位置时沿用最后导入的材料。主动打开已有位置会更新上次阅读时间，「从头阅读」保存开头位置。

## 格式与迁移

| 格式          | 旧版本 | 0.15.0 |
| ------------- | ------ | ------ |
| Library       | 6      | 7      |
| IndexedDB     | 9      | 10     |
| SQLite schema | 3      | 4      |
| HTTP API      | 4      | 5      |
| `.repeaty`    | 3      | 4      |
| JSON 备份     | 6      | 7      |

记录表与正文存储不变。版本门槛防止旧客户端写回时丢弃新字段。旧库无需补写阅读位置，已有 ID、卡片、复习记录、检查点和 `cardDrafts` 保留；旧归档与 JSON 仍可恢复。阅读位置随 Source 进入完整备份、重新生成媒体 ID 和快照恢复。单独导出原文只导出正文。

前端校验位置不超过快照长度，纯文本材料不能保存预览位置；Rust 生成 Schema 校验字段，再检查这些跨字段约束。无效更新在事务中回滚。

## 取舍与验证

阅读位置保存到当前库；账户版需要服务在线，桌面上游模式也不落入本地库。没有多设备位置合并或后台同步。

自动保存有短暂等待。页面 / 应用退出前仍在等待或请求中的最后一次移动可能尚未保存；界面提供「保存阅读位置」及保存状态，不在退出事件中声称异步写入必定完成。失败后的待保存队列只在本次运行中保留。

验证包含旧 IndexedDB / SQLite 升级、旧备份导入、新备份和快照往返、配额与服务失败、切库后的过期响应；三版本覆盖长原文、Markdown、重复文本、Unicode、窗口变窄和继续阅读，并比较原卡片及调度记录。Linux 原生 WebKit / Tauri 测试完全退出并重开应用，分别恢复原文与预览位置。优先级、延后、归档、ReadingTopic、PDF 和网页抓取不在本次范围内。

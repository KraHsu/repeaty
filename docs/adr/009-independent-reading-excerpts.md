# ADR 009：独立阅读摘录

- 状态：已实现，随 0.19.0 验收
- 日期：2026-10-20
- 范围：静态版、账户版、桌面本地与上游模式

## 问题

`Note.excerpt` 只能在制卡时保留选区。阅读时需要先收集一段内容，之后单独阅读、安排日期或制卡，不必立即填写问题或创建卡组。

## 决定

沿用 `Source` 和现有正文 Blob，为摘录增加可选 `kind: 'excerpt'` 与 `origin: { sourceId, start, end }`。原材料不补写类型；摘录的正文使用新的不可变媒体 ID，保存选中的原始字符。`origin` 只保存原文 ID 和 UTF-16 位置，不在加载库时重复携带选区正文。

首版只支持「原文 → 一级摘录 → 卡片」。摘录不能再次保存为摘录，包括已经删除原文的摘录；可以从摘录选取更小的部分制卡。没有独立 Fragment 表、嵌套树、父级设置继承或自动阅读间隔。

界面从选区打开「保存为摘录」，可以修改标题，正文只读。保存不需要卡组；摘录复制原材料的格式和外部链接，拥有自己的阅读位置、安排和优先级，默认普通、待阅读。已有阅读轮次不增加新条目，下一轮才出现该摘录。

「用此摘录制卡」将整段填入现有编辑器；局部选区继续使用「用摘录制卡」。问答、双向和挖空仍由现有 NoteEditor 保存。卡片的 `Note.excerpt` 指向摘录自身，复习时可以查看摘录，再把卡片选区偏移加到 `origin.start`，回到原文中的实际位置。重复文字不通过全文搜索定位。

## 事务与校验

`useLibrary.saveSourceExcerpt` 绑定库作用域和父快照 ID，按需读取正文，校验选区，再把新摘录、正文附件与捕获的原文阅读位置一起提交。保存失败保留输入；回调检查组件生命周期与作用域，迟到结果不能改变另一份库的选中材料。

元数据要求摘录不超过 10000 个 UTF-16 单元；原文存在、不是摘录、不是自身，格式一致，范围在原文内且长度与摘录正文长度相同。读取正文时检查 UTF-8、MIME、大小、换行和字符数；选区边界不能拆开代理对。选区中的空白和 BOM 原样保留，不再次应用原文导入的 BOM / 换行归一化。

IndexedDB 在打开写事务前检查新增或内容关联变化的摘录正文，避免等待 Blob 解码时事务自动提交；随后再检查修订号并原子写入。位置、标题、安排和优先级变更不重复读取所有正文。Rust 在事务内校验同样的来源、范围和正文关系；按原文分组验证，最多同时保留一份原文和当前摘录正文。原文快照替换时，两端也重新验证已有摘录。

后端附件仍先单独上传；提交失败时没有部分学习记录，未引用上传按既有规则暂存供重试，再回收。它不新增后端插件或阅读调度服务。

## 删除与备份

删除原文会解除直接引用原文的笔记关联，并移除子摘录的 `origin`。摘录的类型、正文、阅读状态和关联卡片继续保留。删除摘录时，仅解除指向它的 `Note.excerpt`，卡片内容、身份、FSRS 和历史不变。操作前快照可以恢复原关联及正文。

`.repeaty` 和 JSON 备份保存原文、摘录、选区关系与各自的正文；媒体 ID 重建不改变来源 ID。恢复在提交前校验引用和正文一致性，失败不替换当前库。

数据门槛更新为 Library v10、IndexedDB v13、SQLite v7、HTTP API v8、`.repeaty` v7 和 JSON v10。旧数据不产生虚构摘录；原 ID、位置、安排、优先级、进度、检查点和待确认草稿保留。旧客户端拒绝写回新格式，前端、桌面客户端和服务需一起升级。回退使用升级前的完整备份或数据目录。

## 验证

领域与存储测试覆盖重复 Unicode、精确空白、BOM、一级限制、错位 / 伪造正文、父快照替换、独立安排、轮次、删除、快照与两种备份。应用测试覆盖无卡组保存、作用域变化和配额回滚；SQLite v6 与 IndexedDB v12 升级保留已有记录和辅助草稿。

三版本浏览器流程覆盖双语、390px、键盘保存、整段问答与局部挖空、出处高亮、重开、删除、完整备份恢复。配额与服务故障保留表单并可重试；Linux 原生桌面流程实际退出重开，检查独立正文、出处、优先级、卡片及删除原文后的保留。

交互参考 [Foliole 选区提取](../READING_REFERENCES.md)，只采用独立保存选区的最小流程。深层提取、继承、自动间隔和混排继续根据使用反馈决定。

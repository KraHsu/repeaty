# ADR 011：递增阅读间隔

- 状态：已实现，随 0.22.0 验收
- 日期：2026-10-20
- 范围：静态版、账户版、桌面本地与上游模式

## 问题

已有阅读日期和快捷选项，但同一篇材料下次应该隔多久，仍要由使用者记住。第一版采用明确的固定阶梯，不引入新的记忆模型或阅读评分。

## 决定

Source 增加可选 `readingIntervalDays`，仅接受 1、3、7、14、30。它记录上次已确认使用的阶梯；未设置时，下次为 1 天。确认「读过，安排下次」后依次前进，到 30 天后保持该值。确认页同时显示本次间隔和本机日期，按日历加天，继续复用阅读日期队列。

只有 `read` 安排操作推进阶梯。打开、滚动、普通下一篇、取消和保存位置不推进；手动日期、优先级、归档与恢复保留阶梯。归档材料需先恢复再安排递增间隔。`reset-interval` 移除该字段，下一次从 1 天开始，保留已安排日期与其他阅读设置。

原文与独立摘录各自记录，不继承父材料的阶梯。删除父材料只解除出处，摘录已有的间隔保留。间隔不是阅读次数或掌握程度，不用于 FSRS 调度。

## 提交与恢复

`nextReadingInterval` 生成下一阶梯与日期。`arrangeSource` 检查来源、快照、非归档状态和预览的阶梯 / 日期；陈旧确认与跨日后的旧日期不能推进。界面时钟会刷新预览，出现陈旧安排提示后需核对新日期再确认。

应用操作沿用位置与阅读安排的同一事务及操作前快照，成功后才关闭确认页或推进阅读轮次。忙碌时禁用重复提交；失败保留确认和轮次，库修订冲突不会重复推进。异步完成沿用作用域、组件生命周期与轮次身份检查。

事务已提交后，快照列表读取失败只显示「修改已保存」的提示，不把已完成的写入当作失败，也不保留安排确认页要求重试。后续列表读取成功会清除此提示，原快照仍由保存事务保留。

后端继续校验记录并保存，不执行阅读或 FSRS 调度。仅更新间隔不读取所有正文；原文与摘录的正文、出处、卡片和媒体按既有规则处理。

## 数据版本

更新为 Library v11、IndexedDB v14、SQLite v8、HTTP API v9、`.repeaty` v8 和 JSON v11。沿用现有记录表，不新增历史或调度表。版本门槛防止旧客户端解析后写回时丢掉间隔。

旧库及旧备份升级时不补写间隔，保留记录身份、位置、安排、优先级、出处、快照与待确认草稿。新备份和快照包含间隔。前端、桌面客户端与服务需一起升级；回退使用升级前的完整备份或数据目录。

## 验证

领域测试覆盖阶梯上限、日历日期、陈旧确认、重置、手动操作保留、父子独立与删除、双备份格式及 IDB v13 升级。SQLite 测试检查 v7 升级、允许值、非法值回滚、快照、重开与未来版本拒绝。

三个版本的浏览器流程覆盖实际评分后阅读记录不变、确认与取消、原文 / 摘录独立推进、手动日期、归档与恢复、重置、双语窄屏、键盘、重启和备份。存储配额与服务故障验证失败保留阶梯和当前篇，重试只推进一次。原生桌面检查实际退出并重开、日期与位置保留、重置和原学习记录。

账户流程另行模拟写入成功后 `/backups` 返回 503，验证确认页正常关闭、实际只推进一档、后续读取恢复后清除提示。该场景在修复前会保留确认页并显示下一档，修复后通过。

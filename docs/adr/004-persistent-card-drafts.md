# ADR 004：本机制卡草稿持久化

- 日期：2026-10-19
- 状态：采用
- 范围：0.14.0，桌面本地库；更新 ADR 003 的临时草稿与回执语义

## 存储与恢复

IndexedDB 从 v8 升至 v9，增加独立的 `cardDrafts` 表。草稿绑定本地库作用域、来源 ID、不可变正文 media ID 与摘录位置，保留接收顺序。草稿记录自身有 `version: 1`，加载时检查格式、作用域、键与附件完整性。升级不修改正式记录、修订号和检查点。

只持久化已接收的草稿和用户明确保存的编辑。MCP 密钥、分享授权、批次重试表都留在内存；退出、重载、切库后仍需重新连接并分享。切换上游会隐藏本地草稿，切回后恢复，草稿和附件不发送给上游。

每库最多 50 条待确认草稿。草稿与附件 Blob 存在同一记录中，附件沿用每面 8 个、每个 10 MiB 的限制，不占正式媒体表，也不受正式媒体回收影响。加载不读取 Blob 正文。丢弃后删除整条草稿及其附件引用。

草稿不属于 Library，不进入 FSRS、学习修订号、自动快照、JSON 或 `.repeaty` 备份。恢复备份或检查点只替换正式库，现存草稿不被备份覆盖；来源 ID / media ID 或卡组失效时，保留供丢弃，禁止确认。原文位置与内容在最终保存时再次检查。Library v6、SQLite v3、API v4、`.repeaty` v3 沿用原版本。

## 接收与响应丢失

应用先验证整批提议、预留容量，再在同一事务中写入整批草稿，成功后才返回接收回执。容量检查同时发生在持久层，避免两个写入者超过上限；任意一条写入失败则回滚整批。存储不足时，客户端收到 `library-unavailable`，Repeaty 显示具体错误，正式库保持不变。

成功回执的 `draftIds` 表示草稿已写入本机，不是正式笔记 ID。写入成功后，即使回复丢失、超时或分享被撤销，草稿仍可供用户核对。当前选区有效时，客户端使用相同 `requestId` 与内容重试，返回同一回执；已编辑、确认或丢弃的草稿不会被覆盖或重新添加。选区撤销或重启后不能沿用旧编号重放，需重新分享；客户端应先让用户检查现有草稿。

加载与写入结果绑定作用域代次，过期异步结果不能覆盖新工作空间。取消分享不回滚已经提交的本地接收事务，也不保留外部访问授权。

## 编辑与确认

编辑器提供「保存草稿」与「确认并保存卡片」。前者保留文字、题型、格式、卡组、标签和附件，允许空答案与尚未完成的挖空；后者使用正式 Note 校验与摘录校验。关闭编辑器不自动保存本次修改。

确认后，生成笔记、卡片、正式媒体、操作前快照和删除待确认草稿在同一 IndexedDB 事务中完成。草稿已被消费时拒绝再次确认；存储失败则全部回滚，保留草稿和编辑内容，避免重启后重复生成卡片。丢弃也先等待持久删除成功，再移除界面条目。

读取失败或遇到未知草稿版本时显示错误，保留原记录，暂停草稿接收与确认；可重新读取，正式学习库仍可正常使用。不静默清空、自动升级未知记录或把草稿算作已掌握。

## 验证

- v8 → v9 升级保留正式记录、修订号和检查点；重开数据库恢复顺序、未完成文字和附件字节。
- 批量接收中途失败与确认写入失败均完整回滚；重复确认和重试不生成重复笔记。
- 浏览器覆盖长文本、图片、音频、存储不足、回复丢失、来源删除、上游往返、读取错误和丢弃失败。
- 原生 WebKit 通过外部 HTTP / Rust / IPC 接收草稿，明确保存未完成编辑，关闭并重启真实应用后继续确认；授权不恢复。
- 纯静态与账户版继续运行原有流程，不暴露 MCP 或草稿工作台。

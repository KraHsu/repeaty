# ADR 007：手动阅读优先级

- 状态：已发布，0.17.0
- 日期：2026-10-20
- 范围：静态版、账户版、桌面本地与上游模式

## 问题

日期队列可以延后和归档材料，但当天可读的材料只能按日期排列。用户需要先读重要材料，同时保留原来的日期、阅读位置和卡片计划。

## 决定

增加可选 `Source.priority: 'high' | 'normal' | 'low'`。缺省视为普通，不补写旧记录。优先级独立于 `Source.queue`，更改时不创建日期安排；延后、归档和恢复也保留优先级。

待阅读按高、普通、低排列，同档按安排日期、导入时间和 ID 排序；没有安排时使用导入日期。全部材料仍先列待阅读，再列稍后阅读和归档。后两组维持日期顺序，高优先级不会使未来材料提前可读，也不会恢复归档材料。滚动与保存位置不改变排序。

阅读器提供有文字标签的选择框，列表显示高、低优先级。调整后保留当前材料和阅读位置；如果排序跨页，列表跟随当前材料。重新进入材料页面仍打开待阅读中最近保存位置的材料。中英文、窄屏和键盘使用同一控件。

## 保存与兼容

复用 `useLibrary.arrangeSource`，同时校验当前库、来源 ID 与不可变快照 ID，将优先级与当前可捕获的阅读位置放在同一事务中保存。只有提交成功才更新选择框；失败保留原设置、材料和错误提示。后续位置自动保存从当前 Source 合并，不覆盖优先级。操作前快照、完整备份和媒体重编号均保留该字段，独立原文导出仍只有正文。

优先级只影响阅读，不更新笔记、卡片、练习、评分或 FSRS。服务端只存储和验证材料记录，不增加队列服务或插件接口。

| 格式          | 0.16.0 | 0.17.0 |
| ------------- | ------ | ------ |
| Library       | 8      | 9      |
| IndexedDB     | 11     | 12     |
| SQLite schema | 5      | 6      |
| HTTP API      | 6      | 7      |
| `.repeaty`    | 5      | 6      |
| JSON 备份     | 8      | 9      |

记录表不变，版本门槛防止旧客户端写回时丢失优先级。客户端与服务需一起更新；旧库、检查点、制卡草稿和旧备份继续保留。

## 验证与后续

覆盖缺省普通、三档排序与日期先后、未来和归档材料、高低优先级切换、不可变内容及学习记录、旧库迁移、备份重编号和快照恢复。三版本浏览器流程检查即时重排、阅读位置、归档与延后、刷新、双语和窄屏；配额或服务错误检查回滚与重试。Linux 原生流程完全退出重开应用，检查优先级、安排和原卡片记录。

参考 [Foliole](../READING_REFERENCES.md) 的阅读安排与摘录流程。其数值优先级、父级继承、自动间隔和混合队列不直接引入本版；自动轮换、独立片段和再次提取仍需单独确定需求。

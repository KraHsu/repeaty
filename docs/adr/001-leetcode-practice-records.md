# LeetCode 练习与提交记录

状态：采用；2026-10-18。范围仅限现有 LeetCode 题型，数值题和其他裁判暂缓。

## 原因

当前草稿保存最新代码和结果，评分仅保存 Assessment 摘要；完成后草稿删除，无法回看每次提交。需要独立保存证据，同时沿用 Note / Card、插件接口和 ts-fsrs。

## 决定

- 一轮单卡练习为 Practice，含原始题目快照、开始时间、内容版本和完成方式；多轮练习复用同一 Card ID。
- 每次正式提交创建一个 Attempt，保存语言、原始代码、提交时间、累计作答用时、提交编号与判题结果。先保存提交意图，再访问 LeetCode。
- 提交状态依次为 submitting、pending、completed；明确失败为 failed，响应丢失或中断为 unknown。不将网络异常当作答案错误，不自动重提代码。
- 评估结果保存在对应 Attempt，重试查询更新同一条记录，不新增一次提交。正式提交次数只统计取得编号的记录，未知提交单独提示。
- unknown 可经用户关联已有提交恢复为 pending：本机客户端核对所属账号、题目、语言、代码和时间，沿用原 Attempt ID；同站同插件的正式提交不能重复关联。恢复不重发代码，不修改已完成练习的评分。
- Practice 与 Attempt 是独立记录集合，进入当前 IndexedDB / SQLite 库和备份。原始代码不放入 Assessment 摘要；题目快照不含 Cookie。
- 用户确认时，将 Practice 的最终评分关联到现有 Review，并与调度一起保存。只练习保存完成记录，但没有 Review，也不消耗每日额度。
- 撤销沿用现有最后一次 Review 的恢复逻辑；清除 Practice 的有效评分关联并标记撤销，保留全部提交证据。完整追加评分日志另行设计。
- 恢复旧库时两个新集合为空，不根据旧摘要编造代码或提交历史。移除卡片时级联清理其 Practice 与 Attempt。
- 题面快照不跟随编辑变化；新的练习按当前题目开始。完成后重新练习创建新 Practice，不能重复确认同一 Practice。
- 记录写入校验所属卡片、插件与当前工作空间；未挂载或切库后的请求不能写入新库。临时编辑草稿使用稳定的库作用域；旧版无作用域草稿只允许在本地模式迁入。

## 兼容

数据模型升到 v5、IndexedDB 升到 6、后端数据接口升到 v3、SQLite schema 升到 2、.repeaty 容器升到 2。读取旧库和旧包时迁移；旧客户端遇到新库或新包应拒绝，避免删除它不认识的集合。不改变现有卡片 ID、调度状态和媒体。

## 验收样例

1. 一次 WA 后 AC：两次代码和结果均保留；确认评分产生一个 Review，重启和备份往返一致。
2. 查询失败：记录为 pending，可重新查询，提交次数不增加；响应丢失保留 unknown，不自动再次提交。
3. 保存失败：尚未保存提交意图则不访问 LeetCode；评分失败不清草稿、不前进队列，可以重试。
4. 只练习与撤销：前者保留代码但不调度；后者恢复调度、额度及副作用，提交历史仍在。
5. 编辑题目、账户切换、endpoint 切换、重复回调不能污染其他练习或账户。第三方登录凭据不进入任何学习备份。

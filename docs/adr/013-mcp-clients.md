# ADR 013：Codex 与 Claude 的本机 MCP 接入

- 状态：已实现，0.25.0
- 日期：2026-10-20
- 范围：桌面本地学习库

## 问题

现有 MCP 使用随机本机端口与临时密钥，每次开启都需修改客户端配置。Claude Desktop 的本地服务器使用 stdio；不能要求用户另装代理，也不能让独立进程绕过 WebView 中的应用操作读写主库。

## 选择

复用桌面程序，增加 `--mcp-stdio --connection-file <绝对路径>`。该入口在 Tauri 初始化前运行，使用同一固定版本 rmcp SDK，发布相同的五个工具和安全说明。不会打开 GUI、读取主库或恢复 MCP 授权。初始化与工具发现允许在应用离线时完成，调用返回 `library-unavailable`，以便开启应用后直接重试。

设置页分别生成 Codex TOML、Claude Code / Claude Desktop JSON，并保留通用 HTTP 配置。stdio 配置仅含当前可执行程序与连接文件的绝对路径，不含密钥；路径经结构化编码保留空格、Unicode 和 Windows 反斜杠。不自动编辑客户端配置。

## 当前连接的发现与撤销

应用仅在用户开启 MCP 时，将版本、随机 loopback URL 与临时 token 原子写入应用数据目录的 `mcp.connection.json`。临时文件在 Unix 下仅所属用户可读写。独立锁文件由应用持有 OS 独占锁，防止两个实例覆盖连接；锁文件自身不含密钥。

stdio 每次工具调用重新读当前连接，要求锁仍被持有、文件不超过 4096 字节、格式正确、64 位十六进制 token，以及严格的 `http://127.0.0.1:<非零端口>/mcp` 地址。拒绝用户信息、查询、fragment、其他主机与路径；请求禁用代理和重定向。应用异常退出后，即使留下连接文件或端口被复用，也不能凭无主文件建立连接。

关闭、重载或切库时，在独占锁释放前删除文件，同时撤销原监听与分享。重启后用户仍需开启 MCP、重新分享；同一 stdio 会话随后可发现新端口与 token，不需改配置。安装位置变化则重新生成配置。

本机同用户进程仍可读取自己的应用文件；本方案不声称隔离恶意本机程序或提供远程访问控制。已有 Bearer、Host、Origin、scope、revision、选区与草稿确认检查继续由应用执行。

## 边界与限制

stdio 单帧上限 512 KiB，并发上限 8，单次调用超时 10 秒，结果上限 4 MiB。上游 HTTP 连接不跟随重定向，单次请求超时 8 秒；每次工具调用完成后关闭连接，不自动重试写入。取消和错误不增加新授权。

代理只转发现有工具，原服务与 WebView 再次校验参数、当前库与分享。草稿接收、幂等回执及原子确认沿用 ADR 003 / 004。纯前端和后端网页不包含本地 MCP；桌面上游模式禁止开启。内置模型、API 密钥配置、持久授权与任意文件访问不属于本阶段。

Library / JSON v12、IndexedDB v15、SQLite v9、API v10 和 `.repeaty` v9 保持不变，临时连接文件不进入备份。

## 验证

- Rust 使用官方 SDK 客户端检查离线工具发现、同一 stdio 会话下的端口轮换与恢复、参数和帧上限、独占锁、权限、陈旧 / 超大 / 非本机连接文件。
- 三平台运行真实 release 程序的无界面 stdio smoke，检查初始化、五个工具、离线错误、无效启动参数、过大输入与 EOF 退出。
- 浏览器验证三个客户端的配置选择、复制、隐藏、连接开关、双语、窄屏和上游禁用。
- Linux 原生程序验证真实 stdio 子进程到 Rust / IPC / WebView 的读取、分享、长文本和三类草稿，HTTP 重试不重复接收；窗口重载、退出重开和作用域切换后撤销生效，再次开启可复用原配置。
- 本机 Codex 以进程配置覆盖读取实际生成的 TOML；Claude Code 从临时项目识别 `.mcp.json` 并提示待确认。两者不改用户配置、不调用模型。Claude Desktop 本机 GUI 未运行，配置按官方文档与同一 stdio 协议验证。

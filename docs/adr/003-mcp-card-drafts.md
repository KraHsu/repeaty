# ADR 003：选区授权与待确认制卡草稿

- 日期：2026-10-19
- 状态：采用
- 范围：0.13.0，桌面本地库

本 ADR 记录 0.13.0 的临时草稿实现。0.14.0 的持久化、接收回执和原子确认更新见 [ADR 004](004-persistent-card-drafts.md)。

## 决定

沿用 ADR 002 的本机 HTTP、Bearer 密钥和 IPC Channel。新增读取当前分享摘录、提交卡片草稿两个工具。原有三个学习库查询继续只读；草稿提交标记为非只读、可重试的操作，权限由应用校验，不能依赖 MCP annotations。

用户在材料页选区、核对默认卡组并点击分享后，应用重新读取原文，验证实际位置和文字，为这次选区分配随机 `selectionId`。授权绑定本地库、Source ID、不可变 media ID、选区与默认卡组。客户端只取得选中的文本、标题和卡组，不取得其余正文或来源 URL。

每次只保留一个有效选区。更换选区、停止分享、关闭连接、重载或切库撤销授权。来源或默认卡组被删除、原文被替换后，查询与新提议失败；已收到的草稿保留供用户丢弃，但不能保存失效的来源引用。

## 接收与重试

草稿仅有问答、双向和挖空三类，支持文本、Markdown 和标签。Rust 先验证允许的字段与大小；应用使用严格输入 Schema 和现有 Note 校验检查整批内容。任意一条不合法，整批不接收。

每次分享使用独立的批次表，按 `requestId` 与规范化内容识别重试。相同编号、相同内容返回原回执；不同内容使用相同编号时报冲突，不覆盖旧草稿。用户已保存或丢弃后，重试也不会再加入列表。

应用先暂存待回复批次、预留列表容量；原生桥接接受回复后才显示草稿。取消、超时或旧作用域导致回复被拒绝时，释放暂存内容和容量。并发重试共享同一批次。回执只是接收凭据，既不是持久化承诺，也不是正式笔记 ID。

上限为每批 10 条、每面 10000 字符、问题与答案合计 50000 UTF-16 代码单元、HTTP 请求体 512 KiB。会话内最多 50 条待确认草稿，每次分享最多记住 32 个批次；原生桥接继续限制 8 个并发请求和 4 秒等待。

## 保存

草稿在内存中维护，不写入 Library、IndexedDB 或 SQLite，不进入快照、备份和复习队列。关闭、重载应用或切换学习库会清空；收到草稿不会自动打开编辑器或中断复习。

用户在列表点击「检查并编辑」，复用 NoteEditor 的题型、编辑、预览、标签和附件功能。点击「确认并保存卡片」后，调用现有 `useLibrary.saveExcerptNote`，再次校验本地作用域、原文位置与引用，在同一保存操作中生成笔记和卡片，成功后移除草稿。失败保留编辑内容和待确认项，允许重试。

停止分享或关闭 MCP 不丢弃已经收到的草稿；后续的正式写入仍由用户确认。库和备份格式沿用 0.11.0，不为临时列表新增迁移或服务端插件执行系统。持久草稿、远程账户库、内置模型和自动评分不属于本阶段。

## 验证

- 核心测试：只分享选区，三类草稿与整批校验，幂等、并发重试、回复失败、容量、撤销与切库，删除 / 替换来源，以及正式学习记录不变。
- 浏览器：通过完整材料界面分享，编辑三类草稿，存储不足后保留修改并重试，确认前记录不变，保存后保留出处，重启只保留正式卡片，中英文布局与脚本内容显示。
- 原生桌面：外部 HTTP 客户端通过 Rust / IPC 接收长文本草稿，重试、停止分享、逐条编辑确认，验证正式记录、来源与重载。Rust 测试另验证工具权限提示和大于旧 8 KiB 限额的请求。

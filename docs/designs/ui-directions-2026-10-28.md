# Repeaty UI / UX 方向审查

2026-10-28 · 第一轮已选择 **B · 复习牌组**；用户要求保留原绿色系，允许调整具体配色。

后续审查入口为 [B 方向绿色交互原型](b-prototype/README.md)。保留中央卡组及复习焦点，以森林绿、浅鼠尾草绿和暖白重新配色；独立使用 PrimeVue 4，尚未迁移生产组件库。下方三方向说明记录第一轮候选，原对比页保留作为选择依据。

打开同目录的 [设计对比页](ui-directions-2026-10-28.html)。这是可离线打开的单文件，包含当前界面基线与三版 1440 × 960 首屏。可并排、单张、实际尺寸查看，点击“选择”后将复制的方向反馈到对话。设计稿采用统一虚构学习数据，学习按钮未连接业务。

本轮采用 [oil-ui](https://github.com/oil-oil/oil-ui) 0.26.0 的方向探索流程。不预设 Nuxt UI；组件库由选定方向及实际控件需求决定。生产 UI、依赖和学习数据尚未变更。

| 方向         | 核心设计                                               | 适用体验                       | 后续组件候选                |
| ------------ | ------------------------------------------------------ | ------------------------------ | --------------------------- |
| A · 到期清单 | 连续卡组行，名称、到期、新卡与操作严格对齐；蓝灰中性色 | 快速比较卡组、直接复习         | PrimeVue，统一主题 token    |
| B · 复习牌组 | 中央当前卡组、底部横向队列；卡组容器可承接题面；紫灰色 | 每天打开后专注复习             | shadcn-vue 的可定制组件基础 |
| C · 研读目录 | 导航、卡组目录、阅读内容三列；问答上下分隔；绿色与暖白 | 浏览、编辑、阅读和复习之间切换 | shadcn-vue / Reka UI        |

推荐先考虑 **C**：它直接改善问答阅读层级，目录/内容结构也适合延伸到设置分类与插件 README。若优先追求快速处理复习队列，A 更直接；若希望每日复习有独立而突出的主区域，B 更合适。推荐属于设计判断，尚未代表用户选择。

组件建议根据 [shadcn-vue 官方说明](https://www.shadcn-vue.com/)、[PrimeVue 官方说明](https://primevue.org/) 和本产品所需的表单、分栏、列表、弹窗推导；未安装或评估新库的完整运行时集成。正式落地只选择一套主要控件基础，并统一软件与插件 SDK。

## 共用规则

- 相同数据：4 个卡组、300 张卡片；36 张到期、20 张新卡。当前 FSRS 与 Repeaty 为 27 张，其中 8 张到期、4 张新卡。主按钮均只复习当前卡组。
- 正文与主要控件 16px、辅助 14px；阅读正文 18px；标题与关键数字按固定层级放大。C 仅主要问题采用本地衬线字体，其他界面仍用系统无衬线。
- 插件保留独立入口；README、权限与安装管理留在插件详情，配置进入共享设置分类；设置沿用分支分类的层级表达。
- 删除重复介绍、独立统计卡和无任务贡献的装饰；保留卡组名称、数量、状态与核心动作。次要管理入口降低视觉权重。

## 本轮验证与边界

概念由独立代理生成，另一个独立代理对三张方向卡及灰度结构完成一轮把关，三案通过。根据意见明确主按钮范围，并把 C 的衬线大标题用于实际问题。

已逐张查看真实 Chromium 截图；第一轮发现部分辅助文字对比度不足，修正后再次查看。最终没有文字对比度警告、控制台错误、横向溢出或图片加载失败。A 保留单侧选中线，它用于标识当前卡组，不是装饰性区块边线。

这轮为方向首屏，不含业务交互、动效、移动端、完整设置表单或原生窗口验证；未进行画面打分或完整 UX 走查。待选定后再制作完整页面和关键状态。

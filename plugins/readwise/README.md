# Readwise 来源

将 Readwise Reader 正文、高亮或本地导出接入学习材料。新增、修改和缺失内容先进入来源管理的待确认列表；只有采用后才改变学习库。检查不会覆盖本地修改，也不会切换正在复习的卡片。

## API

1. 在设置 → 连接 → Readwise 保存 [access token](https://readwise.io/access_token)，并测试连接。
2. 在学习材料的来源管理中添加 Readwise，选择 Reader 正文、高亮或两者。
3. 检查来源，审查并采用候选。来源的检查周期由宿主统一管理；应用运行且插件启用时可自动检查。

Token 由桌面原生凭据 API 保存，插件只提交凭据槽引用。Token 不写入学习库、日志、备份或插件设置；它不会发送到正文中的链接或图片站点。API 接入需要桌面版，网页仍可读取用户选择的导出目录。

Reader 使用 `/api/v3/list/` 的 `withHtmlContent` 正文，高亮使用 `/api/v2/export/`。两者用 Reader ID 关联，避免把同一文章重复导入。正文中的活动 HTML 被清理，远程图片不自动下载。扫描保留完整分页结果，成功后统一产生候选；读取失败、取消或凭据改变时丢弃本次不完整结果。

请求按每分钟 20 次节奏发送。限流遵循 `Retry-After`，网络/服务临时错误最多重试 3 次；等待可取消。单次 API 响应最大 1 MiB，单篇正文最大 250,000 字符，一次最多 1,000 篇；超过限制明确报错，不静默截断或推断删除。

## 本地导出目录

选择 Readwise 导出根目录，支持 Markdown、纯文本、HTML，以及 Reader / Highlight API JSON 导出。标准 `Books/书名.md` 与 `Full Document Contents/Books/书名.md` 合成同一材料的正文和高亮。识别 `reader_id`、`user_book_id`、`book_id`、`readwise_url` 等元数据作为稳定身份；没有来源 ID 时使用相对路径。

本地正文中的相对图片、音频和 PDF 链接从已授权目录读取，支持 PNG、JPEG、GIF、WebP、MP3、M4A、OGG、WAV 和 PDF。采用候选时附件一同保存，之后可离线查看；旧材料版本仍引用自己的附件。支持 Markdown 内联链接、引用链接与 HTML 图片/音频，代码示例保持原文。附件路径不得越出所选目录，不读取隐藏目录、临时文件或网络资源。远程图片仍显示占位信息，不会自动请求。

每个导出文本最大 4 MiB、每个内嵌附件最大 10 MiB；单次最多扫描 2,000 个文本文件，正文与去重附件合计最多 128 MiB，合并后最多 1,000 篇材料。超限或取消时不会提交部分结果。

同名 PDF / EPUB 原件与文本配对，仅在明确点击“获取原件”后读取或下载，最大 64 MiB。API 返回的签名下载链接只在本次运行内暂存，不写学习库或备份；过期后需重新检查。原件单独导出，若要用 PDF / EPUB 阅读器阅读，可再通过现有材料导入功能打开，不把文本投影的阅读位置套用到原件。

目录只读，隐藏文件不参与扫描；同一来源同时出现 JSON 与文本等冲突导出时提示选择一种，避免覆盖。移除来源或插件不会删除已采用材料、历史、卡片、调度与旧版本。学习库换设备后需重新授权目录或配置 Token。

API 行为依据 [Readwise API](https://readwise.io/api_deets) 与 [Reader API](https://readwise.io/reader_api) 官方文档。插件不要求 Node.js，不向 Readwise 写回，也不提供账号同步服务。
